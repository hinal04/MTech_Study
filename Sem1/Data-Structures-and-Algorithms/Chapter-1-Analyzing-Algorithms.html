1.1.1 Algorithms and its Specification
Algorithm: A well-defined computational procedure that takes input and produces output. It is a finite sequence of steps that transforms the input into the output.

Counting Primitive Operations

A primitive operation is a low-level instruction with constant execution time: assignment, arithmetic, comparison, array index, method call/return.

Algorithm arrayMax(A, n)
    currentMax ← A[0]              // 2 ops (index + assign)
    for i ← 1 to n-1 do           // 2n ops
        if A[i] > currentMax then  // 2(n-1) ops
            currentMax ← A[i]     // 2(n-1) ops (worst case)
    return currentMax              // 1 op

    Worst case total: 6n - 2  ⇒  Θ(n)
Key insight: The exact count doesn't matter. What matters is that T(n) is a linear function of n. Whether it's 6n-2 or 4n, both are Θ(n). This motivates asymptotic notation.

1.1.2 Random Access Machine (RAM) Model
The RAM model is a theoretical model of computation for machine-independent algorithm analysis.

Assumptions

  1. Single processor — sequential execution, no parallelism
  2. Constant-time operations — arithmetic, comparison, assignment, array indexing, control flow each cost O(1)
  3. Flat memory — unlimited memory, constant-time access to any cell
  4. Fixed word size — w = c·log n bits (can hold an index into the input)

Unit-Cost vs Log-Cost Model

AspectUnit-CostLog-Cost
Arithmetic costO(1) per operationO(log of operand size)
When to useMost algorithm analysisLarge numbers (cryptography)
What RAM ignores: Cache hierarchy (L1 ~1ns vs RAM ~100ns vs disk ~10ms), pipelining, compiler optimizations, multi-core parallelism. Despite this, RAM model predictions are excellent for comparing algorithms.

1.1.4 Algorithm Correctness T1: 1.1.4
An algorithm is correct if, for every valid input, it halts and produces the correct output.

Total Correctness = Partial Correctness + Termination

Preconditions & Postconditions

  • Precondition: What must be true before the algorithm runs (valid inputs)
  • Postcondition: What must be true after the algorithm runs (desired output)

Loop Invariants (3 Properties)

PropertyAnalogyWhat to show
InitializationBase caseTrue before first iteration
MaintenanceInductive stepIf true before iteration, true after
TerminationExtract resultInvariant + exit condition ⇒ correctness

Example: Proving Insertion Sort Correct

InsertionSort(A, n)
    for j ← 1 to n-1 do
        key ← A[j]
        i ← j - 1
        while i ≥ 0 and A[i] > key do
            A[i+1] ← A[i];  i ← i - 1
        A[i+1] ← key

Invariant: At start of each for-loop iteration with index j, subarray A[0..j-1] is sorted.

  • Init (j=1): A[0..0] is one element — trivially sorted. ✓
  • Maintenance: The while-loop shifts elements right and places key in its correct position, so A[0..j] becomes sorted. ✓
  • Termination (j=n): A[0..n-1] is the entire array, and it’s sorted. ✓

Proving Correctness of Recursive Algorithms

Use strong induction on input size. Example for MergeSort:

  • Base (n=1): Single element is sorted. ✓
  • IH: Assume MergeSort correctly sorts any subarray of size < n.
  • Step: Both halves (size < n) are sorted by IH. Merge correctly combines them. ✓

We care about how running time grows as n gets large. We ignore constants and lower-order terms.

T(n) = 6n - 2       → “grows like n”     → Θ(n)
T(n) = 3n² + 5n + 7 → “grows like n²”    → Θ(n²)

1.2.2 Big-Oh, Omega and Theta Notations

Big-Oh: O(g(n)) — Upper Bound (≤)

f(n) = O(g(n)) if there exist c > 0 and n0 such that:
0 ≤ f(n) ≤ c · g(n)   for all n ≥ n0

Meaning: f grows no faster than g. Example: 3n² + 5n = O(n²) with c=4, n0=6.

Big-Omega: Ω(g(n)) — Lower Bound (≥)

f(n) = Ω(g(n)) if there exist c > 0 and n0 such that:
0 ≤ c · g(n) ≤ f(n)   for all n ≥ n0

Meaning: f grows at least as fast as g. Example: 3n² + 5n = Ω(n²) with c=3, n0=1.

Big-Theta: Θ(g(n)) — Tight Bound (=)

f(n) = Θ(g(n)) if there exist c1, c2 > 0 and n0 such that:
c1·g(n) ≤ f(n) ≤ c2·g(n)   for all n ≥ n0

Meaning: f grows at the same rate as g. Equivalent to both O and Ω holding.

Summary of All Five Notations

Important Properties

  • Transitivity: f = O(g) and g = O(h) ⇒ f = O(h)
  • Reflexivity: f = O(f), f = Ω(f), f = Θ(f)
  • Symmetry (Θ only): f = Θ(g) ⇔ g = Θ(f)
  • Transpose: f = O(g) ⇔ g = Ω(f)
  • Sum rule: O(f+g) = O(max(f,g))
  • Product rule: O(f)·O(g) = O(f·g)

1.3 Analyzing Recursive Algorithms R1: Ch 4.3, 4.4, 4.5
Understanding Time Complexity & Recurrences — From Scratch
Before diving into the formal methods, let’s build intuition for how time complexity actually works using simple, traceable examples.

The Core Idea: Count How Many Times the “Main Work” Happens

# Single loop — the print runs n times → O(n)
for i in range(n):
    print(i)

# Nested loop — the print runs n × n times → O(n²)
for i in range(n):
    for j in range(n):
        print(i, j)

# Loop that halves — i takes values n, n/2, n/4, ..., 1 → O(log n)
i = n
while i ≥ 1:
    print(i)
    i = i // 2

What is a Recurrence? (The Simple Version)

A recurrence describes how much work a recursive function does, in terms of smaller versions of itself: 
Total work for input n = Work I do right now + Work my recursive call does

Traced Example 1: Factorial — T(n) = T(n-1) + 1

def factorial(n):
    if n == 0: return 1
    return n * factorial(n - 1)     # 1 call on n-1, plus 1 multiply

Tracing factorial(5):

factorial(5) → 1 multiply + calls factorial(4)
factorial(4) → 1 multiply + calls factorial(3)
factorial(3) → 1 multiply + calls factorial(2)
factorial(2) → 1 multiply + calls factorial(1)
factorial(1) → 1 multiply + calls factorial(0)
factorial(0) → returns 1 (done!)

Total: 5 multiplications. For input n → n multiplications = O(n)

Writing the recurrence:

T(n) = T(n-1) + 1
       ↑         ↑
       │         One multiplication (work at THIS level)
       │
       Cost of solving factorial(n-1)

T(0) = 1   ← base case

Solving by unrolling (just substitute repeatedly):

T(n) = T(n-1) + 1
     = [T(n-2) + 1] + 1 = T(n-2) + 2
     = [T(n-3) + 1] + 2 = T(n-3) + 3
     ...after k steps:  T(n-k) + k

Stops when n-k = 0, so k = n:
T(n) = T(0) + n = 1 + n = O(n)  ✓

Traced Example 2: Binary Search — T(n) = T(n/2) + 1

def binary_search(A, lo, hi, key):
    if lo > hi: return -1
    mid = (lo + hi) // 2
    if A[mid] == key: return mid
    elif key < A[mid]:
        return binary_search(A, lo, mid-1, key)   # LEFT half only
    else:
        return binary_search(A, mid+1, hi, key)   # RIGHT half only

What happens on 16 elements?

Call 1: search 16 elements → 1 comparison → recurse on 8
Call 2: search 8 elements  → 1 comparison → recurse on 4
Call 3: search 4 elements  → 1 comparison → recurse on 2
Call 4: search 2 elements  → 1 comparison → recurse on 1
Call 5: search 1 element   → 1 comparison → done!

Total: 5 comparisons.  16 → 8 → 4 → 2 → 1 = log&sub2; 16 = 4 halvings + 1

Unrolling:

T(n) = T(n/2) + 1
     = T(n/4) + 2
     = T(n/8) + 3
     ...after k steps: T(n/2k) + k

Stops when n/2k = 1  →  k = log&sub2; n

T(n) = 1 + log n = O(log n)  ✓

Traced Example 3: Merge Sort — T(n) = 2T(n/2) + n

def merge_sort(A):
    if len(A) ≤ 1: return A
    mid = len(A) // 2
    left  = merge_sort(A[:mid])     # Sort first half
    right = merge_sort(A[mid:])     # Sort second half
    return merge(left, right)        # Merge: takes n steps

Tracing [5, 3, 8, 1, 2, 7, 4, 6] (n = 8):

                merge_sort([5,3,8,1,2,7,4,6])            ← merge costs 8
               /                                \
  merge_sort([5,3,8,1])              merge_sort([2,7,4,6])     ← 4+4 = 8
     /          \                       /          \
 ms([5,3])   ms([8,1])             ms([2,7])    ms([4,6])      ← 2+2+2+2 = 8
  /    \      /    \                /    \       /    \
[5]   [3]   [8]   [1]            [2]   [7]    [4]   [6]        ← base cases

Count the work at each level:

LevelMergesWork
0 (top)1 merge of 8 items8
12 merges of 4 items8
24 merges of 2 items8
3 (bottom)8 base cases8
Total8 × 4 = 32
Every level does n work. There are log&sub2; n + 1 levels.
For n = 8: 8 × (log&sub2; 8 + 1) = 8 × 4 = 32 = O(n log n)

Unrolling:

T(n) = 2T(n/2) + n
     = 2[2T(n/4) + n/2] + n = 4T(n/4) + n + n = 4T(n/4) + 2n
     = 4[2T(n/8) + n/4] + 2n = 8T(n/8) + n + 2n = 8T(n/8) + 3n

Pattern after k steps: T(n) = 2k · T(n/2k) + k·n

Stops when n/2k = 1 → k = log&sub2; n

T(n) = n · T(1) + n · log n = n + n log n = O(n log n)  ✓

How to Read ANY Recurrence — Cheat Sheet

T(n) = [how many recursive calls] × T([size of each call]) + [work at this level]
You SeeIt MeansResult
T(n) = T(n-1) + 11 call, shrinks by 1, O(1) workO(n)
T(n) = T(n-1) + n1 call, shrinks by 1, O(n) workO(n²) — n+(n-1)+…+1
T(n) = T(n/2) + 11 call, halves, O(1) workO(log n)
T(n) = T(n/2) + n1 call, halves, O(n) workO(n) — n+n/2+n/4+…≈2n
T(n) = 2T(n/2) + 12 calls, halves, O(1) workO(n) — tree has n leaves
T(n) = 2T(n/2) + n2 calls, halves, O(n) workO(n log n) — n × log n levels
T(n) = 2T(n-1) + 12 calls, shrinks by 1O(2n) — doubles every level!
The intuition:
  • Halving (n/2) = logarithmic depth → usually fast
  • Subtracting (n-1) = linear depth → can be slow
  • Number of calls determines if work grows, stays same, or shrinks per level

Master Theorem — Just Pattern Matching

For T(n) = aT(n/b) + nd:

Step 1: Identify a, b, d
   a = number of recursive calls
   b = how much size shrinks (the divisor)
   d = exponent of non-recursive work (if work is n², then d = 2)

Step 2: Compute logb(a)

Step 3: Compare logb(a) with d:
   • logb(a) > d  →  T(n) = O(nlogba)    “recursion wins”
   • logb(a) = d  →  T(n) = O(nd · log n) “tie — multiply by log n”
   • logb(a) < d  →  T(n) = O(nd)           “top-level work wins”

Three Walkthroughs:

RecurrenceabdlogbaCompareResult
2T(n/2) + n22111 = 1 → TIEO(n log n)
4T(n/2) + n42122 > 1 → recursion winsO(n²)
T(n/2) + n12100 < 1 → top-level winsO(n)
Master Theorem in one sentence: Who does more work — the recursive calls piling up at the bottom of the tree, or the non-recursive work at the top?
1.3.1 Recurrence Relations
A recurrence relation defines T(n) in terms of T at smaller inputs. It arises naturally from recursive / divide-and-conquer algorithms.
General divide-and-conquer form:
T(n) = a · T(n/b) + f(n)

a = number of subproblems
b = factor by which size shrinks
f(n) = cost of dividing + combining

1.3.2 Specifying Runtime of Recursive Algorithms

Step-by-Step Method

  1. Identify the base case and its cost
  2. Count the number of recursive calls
  3. Determine the size of each subproblem
  4. Determine the non-recursive work
  5. Write the recurrence

Example: Merge Sort

MergeSort(A, lo, hi)
    if lo < hi then
        mid ← ⌊(lo+hi)/2⌋
        MergeSort(A, lo, mid)       ← T(n/2)
        MergeSort(A, mid+1, hi)     ← T(n/2)
        Merge(A, lo, mid, hi)       ← Θ(n)

Recurrence: T(n) = 2T(n/2) + Θ(n)  ⇒  Θ(n log n)

Example: Binary Search

BinarySearch(A, lo, hi, key)
    if lo > hi then return -1      ← Θ(1)
    mid ← ⌊(lo+hi)/2⌋
    if A[mid] = key return mid
    else if key < A[mid]
        return BinarySearch(lo, mid-1)   ← only ONE call: T(n/2)
    else
        return BinarySearch(mid+1, hi)

Recurrence: T(n) = T(n/2) + Θ(1)  ⇒  Θ(log n)

Example: Quick Sort (Worst vs Average)

Worst case (always 0 : n-1 split):
T(n) = T(n-1) + Θ(n)  ⇒  Θ(n²)

Average case (balanced split):
T(n) = 2T(n/2) + Θ(n)  ⇒  Θ(n log n)
1.3.3 Master Theorem R1: Section 4.5

Master Theorem: T(n) = a · T(n/b) + f(n)

Compare f(n) with nlogb a (the “critical exponent”):

Case 1
f(n) = O(nlogba − ε)
T(n) = Θ(nlogba)
Leaves dominate
Case 2
f(n) = Θ(nlogba)
T(n) = Θ(nlogba · log n)
All levels equal
Case 3
f(n) = Ω(nlogba + ε)
+ regularity
T(n) = Θ(f(n))
Root dominates
Regularity condition (Case 3): a·f(n/b) ≤ c·f(n) for some c < 1. Most polynomial-type functions satisfy this.

When Master Theorem Does NOT Apply

  • Unequal subproblems: T(n) = T(n/3) + T(2n/3) + n
  • Non-polynomial gap: T(n) = 2T(n/2) + n/log n  (gap between Cases 1&2)
  • Subtraction: T(n) = T(n-1) + n  (not division by constant)
  • Non-constant a: T(n) = nT(n/2) + n
1.3.4 Solving Recurrences: Substitution & Recursion Tree R1: 4.3, 4.4

Method 1: Substitution Method (R1: 4.3)

  1. Guess the form of the solution
  2. Prove it correct using mathematical induction

Example: Prove T(n) = 2T(n/2) + n is O(n lg n).

Guess: T(n) ≤ c·n·lg n

Inductive step:
T(n) = 2T(n/2) + n
     ≤ 2·c·(n/2)·lg(n/2) + n
     = c·n·(lg n - 1) + n
     = c·n·lg n - cn + n
     = c·n·lg n + n(1-c)
     ≤ c·n·lg n         when c ≥ 1  ✓

Base: T(2) = 4 ≤ 2c ⇒ c ≥ 2.  ✓
Key technique — Subtracting a lower-order term: If your guess T(n) ≤ cn² fails, try T(n) ≤ cn² - dn. The extra term gives “room” to absorb leftover terms.

Example: T(n) = 4T(n/2) + n — prove O(n²).

Attempt 1 (fails): T(n) ≤ cn²
  → T(n) ≤ cn² + n  ← stuck!

Attempt 2 (works): T(n) ≤ cn² - dn
  T(n) ≤ 4(c(n/2)² - dn/2) + n
     = cn² - 2dn + n
     = cn² - dn + n(1-d)
     ≤ cn² - dn         when d ≥ 1  ✓
Changing variables: For T(n) = 3T(√n) + lg n, let m = lg n to get S(m) = 3S(m/2) + m, then apply Master Theorem.

Method 2: Recursion Tree Method (R1: 4.4)

  1. Draw the tree of recursive calls
  2. Compute the cost at each level
  3. Count the number of levels
  4. Sum across all levels (often geometric series)

Example 1: T(n) = 2T(n/2) + cn  (Merge Sort)

Level 0:   cn           → Total: cn
Level 1:   cn/2 + cn/2  → Total: cn
Level 2:   4 × cn/4    → Total: cn
  ...
Level i:   2i × cn/2i   → Total: cn     (every level = cn!)
  ...
Level lg n: n × c      → Total: cn

Answer: cn × (lg n + 1) = Θ(n log n)
(Equal work at every level — Case 2 behavior)

Example 2: T(n) = 3T(n/4) + cn²

Level i: 3i nodes, each c(n/4i)²  →  Total: (3/16)i · cn²

Ratio = 3/16 < 1  (DECREASING series)

T(n) < cn² · 1/(1 - 3/16) = cn² · 16/13 = Θ(n²)
(Root dominates — Case 3 behavior)

Example 3: T(n) = T(n/3) + T(2n/3) + cn  (Unequal split — Master fails)

Every full level sums to cn.
Shortest path: log&sub3; n levels.  Longest path: log3/2 n levels.
Both are Θ(log n), so T(n) = Θ(n log n)

Example 4: T(n) = 4T(n/2) + cn

Level i: 2i · cn  (ratio = 2 > 1, INCREASING)
Leaves: nlog24 = n² dominate.  T(n) = Θ(n²)

Choosing the Right Method

Recommended workflow: Try Master Theorem first. If it doesn’t apply, draw a Recursion Tree to get a guess, then verify with Substitution.

Problem 1: Analyze PrefixAverages

Algorithm PrefixAverages(X, n)
    for i ← 0 to n-1 do
        s ← 0
        for j ← 0 to i do
            s ← s + X[j]
        A[i] ← s / (i+1)

Answer: Inner loop: Σ(i+1) = n(n+1)/2. T(n) = Θ(n²)

Problem 2: Growth Rate Ordering

Order: (log n)², √(2n), n2/3, n, 2log n, n log n, n², 2n, n!

Answer: Note 2log&sub2; n = n and √(2n) = Θ(n1/2).

(log n)² < n1/2 < n2/3 < n = 2log n < n log n < n² < 2n < n!

Problem 3: Prove log(n!) = Θ(n log n)

Upper: n! ≤ nn ⇒ log(n!) ≤ n log n = O(n log n)

Lower: n! ≥ (n/2)n/2 ⇒ log(n!) ≥ (n/2)log(n/2) = Ω(n log n)

∴ log(n!) = Θ(n log n)

Problem 4: Master Theorem

T(n) = 7T(n/2) + n². a=7, b=2, nlog&sub2; 7 ≈ n2.81. f(n) = n² = O(n2.81-ε) → Case 1.

T(n) = Θ(nlg 7) ≈ Θ(n2.81)

Problem 5: Recursion Tree

T(n) = T(n/4) + T(n/2) + n². Level cost ratio ≈ 5/16 < 1 (decreasing).

T(n) ≤ cn² · 16/11 = Θ(n²). Root dominates.

Problem 6: Substitution with Lower-Order Subtraction

Prove T(n) = 4T(n/2) + n is O(n²).

Guess T(n) ≤ cn² - dn:
T(n) ≤ 4(c(n/2)² - dn/2) + n = cn² - 2dn + n = cn² - dn + n(1-d)
≤ cn² - dn   when d ≥ 1.  ✓

Problem 7: Identify Best/Worst/Average Case

Linear search on unsorted array of n elements:

  • Best: O(1) — element at position 0
  • Worst: O(n) — element not present
  • Average: O(n) — expected (n+1)/2 comparisons
