2.1 Stacks R1: 10.1
2.1.1 Stack ADT
Definition: A stack is a LIFO (Last In, First Out) collection — the last element inserted is the first removed. Think of a stack of plates: you add plates on top and remove from the top.
OperationDescriptionTime
push(x)Insert element x on top of the stackO(1)
pop()Remove and return the top elementO(1)
top() / peek()Return top element without removing itO(1)
isEmpty()Return true if the stack has no elementsO(1)
size()Return the number of elementsO(1)
Errors: pop() or top() on empty stack → Underflow Error. push() on full fixed-size stack → Overflow Error.

Formal ADT Definition

ADT Stack:
    Data:
        A sequence of elements with a designated "top"

    Operations:
        push(x)    : Add x to the top
        pop()      : Remove and return the top element
                     Precondition: stack is not empty
        top()      : Return the top element without removing
                     Precondition: stack is not empty
        isEmpty()  : Return true if no elements exist
        size()     : Return the count of elements

    Errors:
        pop() or top() on empty stack → Underflow Error
        push() on full stack (fixed-size) → Overflow Error
2.1.2 Array-Based Implementation

The simplest implementation uses an array and an integer top tracking the index of the topmost element. top = -1 means empty.

Data Structure

struct Stack:
    array[0..capacity-1]   // fixed-size array
    top = -1               // index of top element; -1 means empty
    capacity               // maximum size

Pseudocode Operations

push(S, x):
    if S.top == S.capacity - 1:
        error "Stack Overflow"
    S.top = S.top + 1
    S.array[S.top] = x

pop(S):
    if S.top == -1:
        error "Stack Underflow"
    x = S.array[S.top]
    S.top = S.top - 1
    return x

top(S):
    if S.top == -1:
        error "Stack Underflow"
    return S.array[S.top]

isEmpty(S):
    return (S.top == -1)

size(S):
    return S.top + 1

C Implementation

#define MAX 100

struct Stack {
    int arr[MAX];
    int top;
};

void init(struct Stack* s) {
    s->top = -1;
}

int isEmpty(struct Stack* s) {
    return s->top == -1;
}

int isFull(struct Stack* s) {
    return s->top == MAX - 1;
}

void push(struct Stack* s, int x) {
    if (isFull(s)) { printf("Overflow\n"); return; }
    s->arr[++(s->top)] = x;
}

int pop(struct Stack* s) {
    if (isEmpty(s)) { printf("Underflow\n"); return -1; }
    return s->arr[(s->top)--];
}

int peek(struct Stack* s) {
    if (isEmpty(s)) { printf("Empty\n"); return -1; }
    return s->arr[s->top];
}

Pros and Cons

ProsCons
O(1) for all operationsFixed size — must know maximum in advance
Cache-friendly (contiguous memory)Wastes space if stack is mostly empty
Simple implementationOverflow if capacity exceeded
2.1.3 Linked-List Implementation

Use a singly linked list with push and pop at the head — no need to traverse.

Data Structure

struct Node:
    data
    next → Node (or NULL)

struct Stack:
    head → Node (or NULL)
    size = 0

Operations

push(S, x):
    newNode = create Node with data = x
    newNode.next = S.head
    S.head = newNode
    S.size++

pop(S):
    if S.head == NULL:
        error "Stack Underflow"
    x = S.head.data
    temp = S.head
    S.head = S.head.next
    free(temp)
    S.size--
    return x
ProsCons
Dynamic size — no overflow (until memory exhausted)Extra memory for pointers
No wasted spaceNot cache-friendly (nodes scattered in memory)
O(1) push/pop at headSlightly slower due to memory allocation per push

Infix: A + B * C (operators between operands)
Postfix: A B C * + (operators after operands — no parentheses needed)

Application 4: Function Call Stack

Every time a function is called, the system pushes a stack frame containing:

  • Local variables
  • Return address
  • Parameters

When the function returns, its frame is popped. This is why:

  • Recursion works — each recursive call gets its own frame.
  • Stack overflow occurs when recursion is too deep (too many frames).

Application 5: Iterative DFS (Depth-First Search)

DFS_Iterative(graph, start):
    stack = empty Stack
    push(start)
    while stack is not empty:
        v = pop()
        if v is not visited:
            mark v as visited
            process v
            for each neighbour u of v:
                if u is not visited:
                    push(u)

2.2.1 Queue ADT
Definition: A queue is a FIFO (First In, First Out) collection — the first element inserted is the first removed. Think of a line at a ticket counter.
OperationDescriptionTime
enqueue(x)Insert element x at the rearO(1)
dequeue()Remove and return the front elementO(1)

isEmpty()Return true if queue has no elementsO(1)
size()Return the number of elementsO(1)

Formal ADT Definition

ADT Queue:
    Data:
        A sequence of elements with a designated "front" and "rear"

    Operations:
        enqueue(x) : Add x to the rear
        dequeue()  : Remove and return the front element
                     Precondition: queue is not empty
        front()    : Return the front element without removing
        isEmpty()  : Return true if no elements exist
        size()     : Return the count of elements

    Errors:
        dequeue() or front() on empty queue → Underflow Error

2.2.2 Circular Array Implementation
Why circular? A naive linear array wastes space as elements are dequeued (front moves right, leaving empty slots at the beginning that can't be reused without shifting all elements). A circular array wraps around using mod, reusing freed slots with zero shifting.

Data Structure

struct Queue:
    array[0..capacity-1]
    front = 0          // index of front element
    rear = 0           // index of next insertion point
    count = 0          // number of elements
    capacity

Pseudocode Operations

enqueue(Q, x):
    if Q.count == Q.capacity:
        error "Queue Overflow"
    Q.array[Q.rear] = x
    Q.rear = (Q.rear + 1) mod Q.capacity    // wrap around!
    Q.count++

dequeue(Q):
    if Q.count == 0:
        error "Queue Underflow"
    x = Q.array[Q.front]
    Q.front = (Q.front + 1) mod Q.capacity  // wrap around!
    Q.count--
    return x

Visualization of Circular Array

Initial state (capacity=5, empty):
  [_] [_] [_] [_] [_]
   ↑front              ↑rear (both at 0)

After enqueue(10), enqueue(20), enqueue(30):
  [10] [20] [30] [_] [_]
   ↑front          ↑rear (at 3)

After dequeue() → returns 10:
  [_] [20] [30] [_] [_]
       ↑front     ↑rear

After enqueue(40), enqueue(50):
  [_] [20] [30] [40] [50]
       ↑front              ↑rear (at 0, wrapped!)

After enqueue(60):
  [60] [20] [30] [40] [50]
        ↑front ↑rear (at 1)    // rear wrapped to fill the gap

The mod operator makes it circular — when rear or front reaches the end, it wraps back to 0.

C Implementation

#define MAX 100

struct Queue {
    int arr[MAX];
    int front, rear, count;
};

void init(struct Queue* q) {
    q->front = q->rear = q->count = 0;
}

int isEmpty(struct Queue* q) { return q->count == 0; }
int isFull(struct Queue* q) { return q->count == MAX; }

void enqueue(struct Queue* q, int x) {
    if (isFull(q)) { printf("Overflow\n"); return; }
    q->arr[q->rear] = x;
    q->rear = (q->rear + 1) % MAX;
    q->count++;
}

int dequeue(struct Queue* q) {
    if (isEmpty(q)) { printf("Underflow\n"); return -1; }
    int x = q->arr[q->front];
    q->front = (q->front + 1) % MAX;
    q->count--;
    return x;
}
2.2.3 Linked-List Implementation & Deque

Linked-List Queue

Enqueue at tail, dequeue at head — both O(1) with a tail pointer.

enqueue(Q, x):
    newNode = create Node(data=x, next=NULL)
    if Q.tail ≠ NULL:
        Q.tail.next = newNode
    Q.tail = newNode
    if Q.head == NULL:
        Q.head = newNode
    Q.size++

dequeue(Q):
    if Q.head == NULL: error "Underflow"
    x = Q.head.data
    temp = Q.head
    Q.head = Q.head.next
    if Q.head == NULL:
        Q.tail = NULL    // queue became empty
    free(temp)
    Q.size--
    return x

Double-Ended Queue (Deque)

A deque (pronounced “deck”) allows insertion and removal at both ends.

OperationTime
insertFront(x) / insertRear(x)O(1)
removeFront() / removeRear()O(1)

Implementation: Doubly linked list or circular array.

Use cases: A deque can function as both a stack AND a queue. Used in sliding window maximum, 0-1 BFS (0-weight edges go to front, 1-weight to rear), and palindrome checking.
2.2.5 Queue Applications

Application 1: BFS (Breadth-First Search)

BFS(graph, start):
    queue = empty Queue
    enqueue(start)
    mark start as visited
    while queue is not empty:
        v = dequeue()
        process v
        for each neighbour u of v:
            if u is not visited:
                mark u as visited
                enqueue(u)

BFS visits all vertices at distance d before any at distance d+1. Gives shortest paths in unweighted graphs.

Application 2: Task Scheduling (FIFO)

Operating systems use queues for:

  • Process scheduling — Ready queue of processes waiting for CPU time.
  • Print spooling — Print jobs served in order of arrival.
  • I/O request handling — Disk requests queued and served in order.

Application 3: Level-Order Tree Traversal

LevelOrder(root):
    if root == NULL: return
    queue = empty Queue
    enqueue(root)
    while queue is not empty:
        node = dequeue()
        print node.data
        if node.left ≠ NULL: enqueue(node.left)
        if node.right ≠ NULL: enqueue(node.right)

Application 4: Producer-Consumer Buffer

A queue acts as a buffer between a producer (adding items) and a consumer (processing items). Used in multithreaded programming, message passing, and streaming systems.

2.3 Amortised Analysis R1: 17.1
2.3.1 Why Amortised Analysis?

Sometimes an operation is usually cheap but occasionally expensive. Worst-case analysis over-counts by assuming every operation is expensive.

Amortised analysis gives the average cost per operation over a worst-case sequence of n operations. It's NOT average-case analysis (which assumes a probability distribution).

Analysis TypeWhat it measures
Worst-caseMaximum cost of a single operation.
Average-caseExpected cost assuming a probability distribution over inputs.
AmortisedAverage cost per operation over ANY sequence of n operations. No probability assumption — deterministic.
2.3.2 The Aggregate Method

The simplest amortised analysis technique:

Amortised cost per operation = (Total cost of n operations) / n

Key: Compute the total cost of a worst-case sequence, then divide by n.

2.3.3 Stack MULTIPOP — Amortised O(1)

Consider a stack with three operations:

  • PUSH(x) — cost 1
  • POP() — cost 1
  • MULTIPOP(k) — pop min(k, stack_size) elements. Cost = min(k, stack_size).
Naive analysis (too pessimistic): A single MULTIPOP can cost O(n) (pop everything). So worst case for n operations = O(n²)? Wrong!

Aggregate Analysis (Correct)

Key insight: Each element can be popped at most once for each time it is pushed.

  • Over n operations, the number of PUSHes ≤ n.
  • The total number of POPs (from POP + MULTIPOP combined) ≤ total PUSHes ≤ n.
  • Total cost of all POPs and MULTIPOPs ≤ n.
  • Total cost of all PUSHes ≤ n.
Total cost ≤ 2n. Amortised cost per operation = 2n / n = O(1).

Worked Example

OperationCostStack
PUSH(1)1[1]
PUSH(2)1[1, 2]
PUSH(3)1[1, 2, 3]
MULTIPOP(2)2[1]  (popped 3, 2)
PUSH(4)1[1, 4]
PUSH(5)1[1, 4, 5]
MULTIPOP(5)3[]  (popped 5, 4, 1 — only 3 elements)

Total operations: 7. Total cost: 1+1+1+2+1+1+3 = 10. Amortised: 10/7 ≈ 1.43 = O(1) ✓

Even though MULTIPOP is expensive in isolation, it averages out because you can only pop what you've pushed.

2.3.4 Queue with Two Stacks — Amortised O(1)

A queue implemented using two stacks (S1 and S2):

enqueue(x):
    push x onto S1

dequeue():
    if S2 is empty:
        while S1 is not empty:
            pop from S1 and push onto S2   // Transfer all
    return pop from S2

How it works: S1 is the “input” stack. S2 is the “output” stack. When S2 is empty, we “flip” S1 into S2 — reversing the order for FIFO behaviour.

Naive analysis: A single dequeue might transfer n elements → O(n). So n operations = O(n²)? Too pessimistic!
Aggregate proof: Each element undergoes at most 3 moves in its lifetime:
  1. Pushed onto S1 (during enqueue) — cost 1
  2. Popped from S1 and pushed onto S2 (during transfer) — cost 2
  3. Popped from S2 (during dequeue) — cost 1
Total cost per element ≤ 4. At most n elements → Total ≤ 4n.
Amortised cost = 4n / n = O(1).

Worked Example

OperationS1S2CostOutput
enqueue(1)[1][]1
enqueue(2)[1, 2][]1
enqueue(3)[1, 2, 3][]1
dequeue()[][3, 2, 1] → pop 13+1=41
dequeue()[][3, 2] → pop 212
dequeue()[][3] → pop 313

Total: 6 ops, cost = 1+1+1+4+1+1 = 9. Amortised: 9/6 = 1.5 = O(1) ✓

A dynamic array (C++ vector, Java ArrayList) doubles its capacity when full.

Formal Proof:
Copy costs form geometric series: 1 + 2 + 4 + ... + n < 2n.
Plus n normal insertion costs = n.
Total < 3n. Amortised = 3n / n = O(1).

Why Doubling? Why Not Add a Constant?

Adding constant c (e.g. +10 each time):
Resizes at n/c, 2n/c, 3n/c, ... insertions.
Total copy cost = c + 2c + 3c + ... = c · k(k+1)/2 where k = n/c → O(n²/c) = O(n²).
Amortised = O(n). Not constant!

Doubling gives O(1) amortised. Adding a constant gives O(n) amortised. That's why all standard implementations double.

2.4.2 Singly Linked List — Full Implementation

Each node stores data and a pointer to the next node. Last node points to NULL.

struct Node:
    data
    next → Node (or NULL)

struct SinglyLinkedList:
    head → Node (or NULL)
    size = 0

All Core Operations

insertAtHead(L, x):                           // O(1)
    newNode = Node(data=x, next=L.head)
    L.head = newNode
    L.size++

insertAtTail(L, x):                           // O(n) without tail ptr, O(1) with
    newNode = Node(data=x, next=NULL)
    if L.head == NULL:
        L.head = newNode
    else:
        current = L.head
        while current.next ≠ NULL:
            current = current.next
        current.next = newNode
    L.size++

insertAtPosition(L, i, x):                    // O(i)
    if i == 0: insertAtHead(L, x); return
    current = L.head
    for j = 0 to i-2:
        current = current.next
    newNode = Node(data=x, next=current.next)
    current.next = newNode
    L.size++

deleteAtHead(L):                               // O(1)
    if L.head == NULL: error "Empty"
    temp = L.head
    L.head = L.head.next
    free(temp)
    L.size--

deleteAtPosition(L, i):                        // O(i)
    if i == 0: deleteAtHead(L); return
    current = L.head
    for j = 0 to i-2:
        current = current.next
    temp = current.next
    current.next = temp.next
    free(temp)
    L.size--

search(L, x):                                 // O(n)
    current = L.head; position = 0
    while current ≠ NULL:
        if current.data == x: return position
        current = current.next; position++
    return -1

2.4.3 Doubly Linked List — O(1) Deletion

Each node has pointers to both next and previous nodes. Supports backward traversal.

struct Node:
    data
    prev → Node (or NULL)
    next → Node (or NULL)

struct DoublyLinkedList:
    head → Node (or NULL)
    tail → Node (or NULL)
    size = 0

Operations

insertAtHead(L, x):                           // O(1)
    newNode = Node(data=x, prev=NULL, next=L.head)
    if L.head ≠ NULL:
        L.head.prev = newNode
    else:
        L.tail = newNode
    L.head = newNode
    L.size++

insertAtTail(L, x):                           // O(1)
    newNode = Node(data=x, prev=L.tail, next=NULL)
    if L.tail ≠ NULL:
        L.tail.next = newNode
    else:
        L.head = newNode
    L.tail = newNode
    L.size++

deleteNode(L, node):                          // O(1)!
    if node.prev ≠ NULL:
        node.prev.next = node.next
    else:
        L.head = node.next
    if node.next ≠ NULL:
        node.next.prev = node.prev
    else:
        L.tail = node.prev
    free(node)
    L.size--
Key advantage: O(1) deletion given a node pointer.
In a singly linked list, deleting node X requires traversing from head to find X's predecessor → O(n).
In a doubly linked list, X already knows its predecessor via X.prev → O(1).

Critical for: LRU Cache (move accessed node to front in O(1)).
OperationTime
Insert at head / tailO(1)
Insert after given nodeO(1)
Delete given nodeO(1) ← key advantage
Delete at head / tailO(1)
Search / Access by indexO(n)
2.4.4 Circular Linked List & Array vs. Linked List

Circular Linked List

The last node's next pointer points back to the head instead of NULL.

Singly Circular:
    A → B → C → D → A (back to head)

Doubly Circular:
    A ⇆ B ⇆ C ⇆ D ⇆ A (head.prev = tail, tail.next = head)

Advantages: No NULL checks (always traverse). Natural for round-robin scheduling. Efficient circular buffers.

Implementation note: Detect “full traversal” by checking if we've returned to the starting node.

Array vs. Linked List — Complete Comparison

When to use what:
Use Array: Frequent random access, known size, cache performance, binary search needed.
Use Linked List: Frequent insert/delete at arbitrary positions, unpredictable size, O(1) delete given node pointer.
2.4.6 List Applications

1. Polynomial Representation

Each node stores (coefficient, exponent). Addition/multiplication by traversing both lists.

2. Sparse Matrix Representation

Only non-zero elements stored as (row, col, value) nodes. Saves memory for mostly-zero matrices.

3. Undo/Redo (Doubly Linked List)

Each state is a node. Move backward (undo) or forward (redo) along the list.

4. LRU Cache (Doubly Linked List + Hash Map)

  • Hash map: key → node pointer (O(1) lookup).
  • Doubly linked list: most recently used at head, least at tail.
  • On access: move node to head → O(1).
  • On eviction: remove tail → O(1).

5. Music Playlist (Circular List)

Songs cycle back to the beginning after the last song.

Practice Problems with Solutions

P1. MinStack — O(1) push, pop, top, getMin

Problem: Design a stack supporting push, pop, top, and retrieving the minimum — all in O(1).

Solution: Use two stacks: one for data, one tracking current minimums.

push(x):
    dataStack.push(x)
    if minStack.isEmpty() OR x ≤ minStack.top():
        minStack.push(x)

pop():
    val = dataStack.pop()
    if val == minStack.top():
        minStack.pop()
    return val

getMin():
    return minStack.top()

Why it works: minStack only pushes when a new minimum arrives. When that minimum is popped from dataStack, it's also popped from minStack, revealing the previous minimum.

All operations: O(1) time. O(n) space.

P3. Prove MULTIPOP amortised cost is O(1)

Proof (Aggregate Method):

  1. Over n operations, max PUSH operations ≤ n.
  2. Each element pushed at most once.
  3. Each element popped at most once (by POP or MULTIPOP).
  4. Total pops across all POP and MULTIPOP calls ≤ total pushes ≤ n.
  5. Total cost = (all pushes) + (all pops) ≤ n + n = 2n.
  6. Amortised cost = 2n / n = O(1). ▮

P4. Prove Two-Stack Queue amortised cost is O(1)

Proof (Aggregate Method):

Each element goes through at most 4 moves: push S1 (1) + pop S1 (1) + push S2 (1) + pop S2 (1) = 4.

At most n elements processed. Total cost ≤ 4n. Amortised = 4n/n = O(1). ▮

P5. Reverse a Linked List (Iterative + Recursive)

Iterative

reverse(head):
    prev = NULL
    current = head
    while current ≠ NULL:
        next = current.next
        current.next = prev     // reverse the link
        prev = current
        current = next
    return prev                 // new head

Recursive

reverse(head):
    if head == NULL or head.next == NULL:
        return head
    rest = reverse(head.next)
    head.next.next = head      // next node points back to us
    head.next = NULL            // remove forward pointer
    return rest                 // rest is the new head

Both: O(n) time. Iterative = O(1) space. Recursive = O(n) stack space.

P6. Floyd's Cycle Detection (Tortoise and Hare)

hasCycle(head):
    slow = head
    fast = head
    while fast ≠ NULL AND fast.next ≠ NULL:
        slow = slow.next           // move 1 step
        fast = fast.next.next      // move 2 steps
        if slow == fast:
            return True            // cycle detected
    return False                   // no cycle

Why it works: If there's a cycle, fast will eventually “lap” slow inside the cycle (gains 1 step per iteration). If no cycle, fast reaches NULL.

Time: O(n). Space: O(1).

Finding the Cycle Start

After detecting (slow == fast), reset slow to head. Move both one step at a time. They meet at the cycle start.

Proof: Let d = distance from head to cycle start, k = distance from cycle start to meeting point. When they meet: slow traveled d+k, fast traveled 2(d+k). Difference d+k is a multiple of cycle length L. So d = mL - k. Starting from head (d away) and meeting point (L-k away from cycle start): both reach the cycle start after d steps.
