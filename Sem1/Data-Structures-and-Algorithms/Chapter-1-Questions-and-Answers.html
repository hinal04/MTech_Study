Section A: Conceptual / Theory Questions
1What is an algorithm? State its five essential properties.▾

An algorithm is a well-defined, finite sequence of computational steps that takes some input and produces an output.

Five essential properties:

  1. Input — Zero or more quantities are externally supplied
  2. Output — At least one quantity is produced
  3. Definiteness — Each instruction is clear and unambiguous
  4. Finiteness — The algorithm terminates after a finite number of steps
  5. Effectiveness — Every instruction is basic enough to be carried out in practice
2What are the limitations of experimental analysis? Why prefer theoretical analysis?▾

Limitations of Experimental Analysis:

  1. Algorithm must be fully implemented first
  2. Results only valid for specific inputs tested
  3. Comparisons require same hardware/software environment
  4. Results are not portable across machines

Why Theoretical Analysis is Preferred:

  1. Takes into account all possible inputs
  2. Evaluates speed independent of hardware
  3. Can study at pseudocode level without implementing
  4. Characterizes running time as a function of input size n
3Explain the Random Access Machine (RAM) model and its key assumptions.▾

The RAM model is a theoretical model of computation providing a machine-independent framework.

Key Assumptions:

  1. Single processor — sequential execution
  2. Constant-time operations — arithmetic, comparison, assignment, array indexing each take O(1)
  3. Flat memory — unlimited, constant-time access to any cell
  4. Fixed word size — w = c·log n bits

Ignores: memory hierarchy, caching, parallelism, compiler optimizations, pipelining.

Despite simplifications, an O(n log n) algorithm virtually always beats O(n²) in practice for large n.

6What is a loop invariant? State and explain its three properties.▾

A loop invariant is a logical assertion about the algorithm's state that holds at a specific point in a loop. It is analogous to mathematical induction.

  1. Initialization (Base Case) — true before the first iteration
  2. Maintenance (Inductive Step) — if true before an iteration, remains true after
  3. Termination — when the loop ends, the invariant + termination condition proves correctness

Three steps at each level of recursion:

  1. Divide — break into smaller subproblems
  2. Conquer — solve recursively (or directly for base case)
  3. Combine — merge subproblem solutions

Section C: Asymptotic Notation — Proofs & Comparisons
12Prove that 5n² + 3n + 20 = O(n²).▾

Need c > 0 and n0 such that 5n² + 3n + 20 ≤ c·n² for all n ≥ n0.

For n ≥ 1:
5n² + 3n + 20 ≤ 5n² + 3n² + 20n² = 28n²

Choose c = 28, n₀ = 1.  ✓

Tighter: for n ≥ 5: 5n² + n² + n² = 7n², so c = 7, n0 = 5. ✓

13Prove that 3n³ + 2n² + 5 = Θ(n³).▾

Upper bound (O): 3n³ + 2n³ + 5n³ = 10n³ ⇒ c2 = 10

Lower bound (Ω): 3n³ + 2n² + 5 ≥ 3n³ ⇒ c1 = 3

Θ(n³) with c1 = 3, c2 = 10, n0 = 1. ✓
14Prove that n² ≠ O(n).▾

Suppose n² = O(n). Then n² ≤ c·n ⇒ n ≤ c for all n ≥ n0.

But n grows without bound, so no finite c works. Contradiction.

Therefore n² ≠ O(n). ✓
15Prove or disprove: 2n+1 = O(2n).▾

TRUE

2n+1 = 2 · 2n ≤ 2 · 2n

Choose c = 2, n₀ = 1.  ✓
The constant factor 2 is absorbed. In fact 2n+1 = Θ(2n).
16Prove or disprove: 22n = O(2n).▾

FALSE

22n = (2n)². We'd need (2n)² ≤ c·2n, i.e., 2n ≤ c. But 2n → ∞. Contradiction.

Key lesson: 22n is exponentially larger than 2n. Don't confuse with 2n+1 = 2·2n which IS O(2n).

21Time complexity of triple-nested loop (each 1 to n)?▾
for i ← 1 to n do
    for j ← 1 to n do
        for k ← 1 to n do
            x ← x + 1

n × n × n = n³ executions of the innermost statement.

T(n) = Θ(n³)
22Analyze: inner loop j ← 1 to i inside i ← 1 to n.▾
Total = Σ i for i = 1 to n = 1 + 2 + ... + n = n(n+1)/2
T(n) = Θ(n²)
23Analyze: outer loop halves, inner loop doubles.▾
i ← n
while i ≥ 1 do
    j ← i
    while j ≤ n do
        x ← x + 1;  j ← 2*j
    i ← i/2

Outer: i = n, n/2, ..., 1 → log n + 1 iterations.

For i = n/2k: inner runs k + 1 times.

Total = Σ(k+1) for k = 0 to log n = (log n + 1)(log n + 2)/2
T(n) = Θ(log² n)
24Analyze: linear outer × logarithmic inner (j doubles).▾

Outer loop: n times. Inner loop: j = 1, 2, 4, ... until j ≥ n → log n iterations.

T(n) = Θ(n log n)
25Analyze: inner loop runs i² times.▾
Total = Σ i² for i = 1 to n = n(n+1)(2n+1)/6
T(n) = Θ(n³)
26Two sequential blocks: nested n×n loop, then single n loop.▾

Block 1: Θ(n²). Block 2: Θ(n). By sum rule:

T(n) = Θ(n²) — dominant term wins.
Section E: Loop Invariants & Correctness Proofs
27Prove Selection Sort correct using a loop invariant.▾
SelectionSort(A, n)
    for i ← 0 to n-2 do
        min ← i
        for j ← i+1 to n-1 do
            if A[j] < A[min] then min ← j
        swap(A[i], A[min])

Invariant: At start of iteration i, A[0..i-1] contains the i smallest elements in sorted order.

Initialization (i = 0):

A[0..-1] is empty — trivially sorted. ✓

Maintenance:

Inner loop finds min element in A[i..n-1]. After swap, A[0..i] has the (i+1) smallest elements sorted. ✓

Termination (i = n-1):

A[0..n-2] sorted with smallest n-1 elements. Remaining A[n-1] must be largest. Entire array sorted. ✓

28State a loop invariant for Binary Search and prove correctness.▾

Invariant: If key exists in A, then key is in A[lo..hi].

Initialization:

lo=0, hi=n-1 covers entire array. ✓

Maintenance:

  • A[mid] = key ⇒ return mid (correct!) ✓
  • key < A[mid] ⇒ key can't be in A[mid..hi]; set hi ← mid-1 ✓
  • key > A[mid] ⇒ key can't be in A[lo..mid]; set lo ← mid+1 ✓

Termination:

lo > hi means range is empty. Key would need to be in an empty range — contradiction. Returning -1 is correct. ✓

Termination proof: (hi - lo) strictly decreases each iteration.

29Prove Power(a, n) correctly computes an.▾
Power(a, n)
    if n = 0 return 1
    if n is even:  half ← Power(a, n/2); return half × half
    else:          return a × Power(a, n-1)

Proof by strong induction on n:

Base (n=0): Returns 1 = a&sup0;. ✓

Even n: half = an/2 (by IH). Returns an/2 · an/2 = an. ✓

Odd n: Returns a · an-1 (by IH) = an. ✓

Terminates: n strictly decreases each call, base case at 0. ✓

Section I: Substitution Method
37Prove T(n) = 2T(n/2) + n is O(n log n) by substitution.▾

Guess: T(n) ≤ c·n·lg n

T(n) = 2T(n/2) + n
     ≤ 2·c·(n/2)·lg(n/2) + n
     = c·n·(lg n - 1) + n
     = c·n·lg n - cn + n
     = c·n·lg n + n(1 - c)
     ≤ c·n·lg n           when c ≥ 1  ✓

Base: T(2) = 4 ≤ c·2·1 = 2c ⇒ c ≥ 2. ✓

38Prove T(n) = T(n-1) + n is O(n²) by substitution.▾

Guess: T(n) ≤ c·n²

T(n) ≤ c(n-1)² + n
     = cn² - 2cn + c + n
     = cn² + n(1-2c) + c
     ≤ cn²              when c ≥ 1  ✓
39Prove T(n) = 4T(n/2) + n is O(n²) — subtracting lower-order term technique.▾

Attempt 1 (fails):

Guess T(n) ≤ cn²:
T(n) ≤ 4c(n/2)² + n = cn² + n    ← NOT ≤ cn². Stuck!

Attempt 2 (works — subtract dn):

Guess T(n) ≤ cn² - dn:
T(n) ≤ 4(c(n/2)² - d(n/2)) + n
     = cn² - 2dn + n
     = cn² - dn + n(1-d)
     ≤ cn² - dn              when d ≥ 1  ✓
Key technique from CLRS 4.3: Subtracting a lower-order term gives “room” to absorb the extra +n.
